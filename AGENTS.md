# AGENTS.md - tokyo-night-intellij project memory

A theme-only IntelliJ plugin porting the four Zed Tokyo Night variants. There is
**no runtime application code** - the shipped artifact is resources: four
`*.theme.json` (UI) and four `*.xml` editor schemes, plus `plugin.xml`. A
stdlib-only Python generator emits them from a pinned upstream palette.

## Landing a change (jj, NOT git)

The owner uses **Jujutsu exclusively** in a colocated repo. **Never invoke `git`** -
it can corrupt jj's operation log. jj has no staging area; the working copy is
always a commit.

1. Make **one focused change** per commit.
2. Run `mise run check`; land only when it passes.
3. For user-visible changes, bump `version` in `gradle.properties` + add a dated
   `CHANGELOG.md` entry in the *same* commit.
4. `jj describe -m "<imperative one-liner>"` then `jj bookmark set main --to @`
   then `jj new`.
5. Invariant: every time `main` moves, the next command is `jj new`, so `@` is
   always an empty commit one above main.

**Landing is strictly local. Agents must NEVER push from this repository.** Do
not run `jj git push`, create a PR as part of landing, or otherwise publish a
landed change. The owner handles all pushes.

Remote: `origin` = `Jarvvski/tokyo-night-intellij` (SSH:
`git@github.com:Jarvvski/tokyo-night-intellij.git`). `gh` auto-detection fails in
jj workspaces - always pass `-R Jarvvski/tokyo-night-intellij`.

## Generated outputs are committed - never hand-edit them

Everything under `src/main/resources/themes/` is generated by
`tools/generate.py`. Edit the generator or its mappings, run the generator, and
commit the result. Do not patch a generated `.theme.json` or `.xml` by hand; the
next regeneration would silently discard it.

`mise run check` fails if regenerating produces a diff against the committed
outputs. When you intentionally change output, run `uv run tools/generate.py`
and commit the regenerated files in the same change.

## Versioning & changelog

Keep a single **version of record**: the `version` property in
`gradle.properties`. Semver: PATCH for fixes, MINOR otherwise; **never bump to
1.0.0 (or any MAJOR) without the owner's explicit approval - do not auto-bump.**

A user-visible change adds a dated `CHANGELOG.md` entry (newest first) in the same
commit; skip pure internal refactors.

## Toolchain

**mise** owns tasks and the toolchain pin (see `mise.toml`). Use the tasks, don't
hand-roll Gradle:

- `mise run check` - the pre-land gate: generator drift check + `buildPlugin`.
- `mise run build` - `./gradlew buildPlugin`.
- `mise run generate` - `uv run tools/generate.py`.

Python runs via **uv**, stdlib only - no third-party dependencies. Gradle runs via
the committed wrapper; the build targets **IPGP 2.19.0**, **Kotlin 2.4.21**, JDK 21.
The target IDE (`intellijIdea("2026.3")`) is an EAP and requires
`useInstaller = false`.

## Kotlin / Gradle conventions

Kotlin DSL throughout (`*.gradle.kts`). Any Java/Kotlin source that ever becomes
necessary is written in **Kotlin**, not Java - but today there is none, so leave
`src/main/kotlin/` empty unless a class is genuinely required.

## Generator conventions

Python, stdlib only. Drive every emitted value from the pinned palette dump; do
not assume variants share values (Moon diverges from Night/Storm in several
roles). Keep mappings declarative in `tools/mappings/*.py`, one module per
subsystem (UI, syntax, scheme colors, diff/VCS, ANSI). Never invent an IntelliJ
attribute id: if a language role cannot be confidently enumerated, fall back to a
platform DEFAULT attribute rather than guessing.
